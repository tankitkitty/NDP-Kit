# สร้างผู้ใช้ฐานข้อมูลแบบอ่านอย่างเดียวให้ NDP-Kit

## ทำไมต้องทำ

ตอนนี้หน่วยบริการส่วนใหญ่ตั้งค่าให้ NDP-Kit ต่อฐาน HOSxP ด้วยบัญชี `sa` ซึ่งมีสิทธิ์
เต็มทั้งเซิร์ฟเวอร์ ตรวจได้ด้วยคำสั่งนี้

```sql
SHOW GRANTS FOR CURRENT_USER();
-- ถ้าได้ GRANT ALL PRIVILEGES ON *.* ... WITH GRANT OPTION แปลว่าสิทธิ์เต็ม
```

NDP-Kit อ่านข้อมูลอย่างเดียวอยู่แล้ว ทุกคำสั่งผ่านตัวกรองที่ปฏิเสธคำสั่งที่ไม่ใช่
`SELECT` แต่การกรองด้วยข้อความไม่มีทางกันได้ครบทุกทาง โดยเฉพาะเมื่อเปิดหน้า
**รายงานที่เขียนเอง** ให้ผู้ใช้พิมพ์คำสั่งเองได้ และรับไฟล์รายงานจากหน่วยอื่นมาใช้

การเปลี่ยนไปใช้บัญชีที่มีสิทธิ์แค่ `SELECT` ทำให้ **ต่อให้หลุดด่านกรองไปได้ ก็ยังเขียน
อะไรลงฐาน HOSxP ไม่ได้อยู่ดี** เพราะเซิร์ฟเวอร์เป็นคนปฏิเสธเอง ไม่ใช่โปรแกรม

## คำสั่งที่ต้องรัน (รันบนเครื่องเซิร์ฟเวอร์ฐานข้อมูล ด้วยบัญชีที่มีสิทธิ์เต็ม)

เปลี่ยน `รหัสผ่านที่ตั้งเอง` เป็นรหัสผ่านที่ยาวและเดายาก แล้วเปลี่ยน `pcu`
เป็นชื่อฐานข้อมูล HOSxP ของหน่วยบริการ (ดูได้จากหน้าตั้งค่าการเชื่อมต่อ)

```sql
-- 1) สร้างบัญชีสำหรับ NDP-Kit โดยเฉพาะ
CREATE USER 'ndpkit'@'localhost' IDENTIFIED BY 'รหัสผ่านที่ตั้งเอง';

-- 2) ให้สิทธิ์อ่านเฉพาะฐาน HOSxP ฐานเดียว ไม่ให้สิทธิ์อื่นเลย
GRANT SELECT ON pcu.* TO 'ndpkit'@'localhost';

-- 3) ให้มีผลทันที
FLUSH PRIVILEGES;
```

ถ้าติดตั้ง NDP-Kit ไว้คนละเครื่องกับฐานข้อมูล ให้เปลี่ยน `'ndpkit'@'localhost'`
เป็น IP ของเครื่องที่ติดตั้ง เช่น `'ndpkit'@'192.168.1.50'` — **อย่าใช้ `'ndpkit'@'%'`**
เพราะเท่ากับเปิดให้ต่อจากเครื่องไหนก็ได้ในเครือข่าย

## สิ่งที่บัญชีนี้ทำไม่ได้ (ตั้งใจให้เป็นแบบนั้น)

| สิทธิ์ | ให้ไหม | เหตุผล |
| --- | --- | --- |
| `SELECT` บนฐาน HOSxP | ✅ ให้ | เป็นสิ่งเดียวที่โปรแกรมต้องใช้ |
| `INSERT` / `UPDATE` / `DELETE` | ❌ ไม่ให้ | โปรแกรมไม่เคยเขียนลงฐาน HOSxP |
| `FILE` | ❌ ไม่ให้ | กันคำสั่งอ่าน/เขียนไฟล์บนเครื่องเซิร์ฟเวอร์ |
| สิทธิ์บนฐาน `mysql` | ❌ ไม่ให้ | ในนั้นมีรหัสผ่านของผู้ใช้ฐานข้อมูลทุกคน |
| `SUPER` / `PROCESS` | ❌ ไม่ให้ | กันการดูหรือแทรกแซงงานของผู้ใช้คนอื่น |

## เปลี่ยนให้ NDP-Kit มาใช้บัญชีใหม่

1. เปิดโปรแกรม → **ตั้งค่าการเชื่อมต่อ**
2. เปลี่ยน **User** เป็น `ndpkit` และใส่รหัสผ่านที่ตั้งไว้
3. กด **ทดสอบการเชื่อมต่อ** ให้ขึ้นว่าสำเร็จก่อน แล้วจึงกดบันทึก

## ข้อจำกัดที่ยังเหลืออยู่

บัญชีอ่านอย่างเดียวกันการ **แก้ไข** ข้อมูลได้ แต่ไม่ได้กันการ **อ่าน** — คนที่เข้าสู่ระบบ
NDP-Kit ได้ยังเขียนรายงานดึงข้อมูลผู้ป่วยออกมาทั้งฐานได้อยู่ ซึ่งเป็นเรื่องปกติของงาน
รายงาน สิ่งที่ต้องคุมคู่กันคือ

- อย่าบอกรหัสเข้าสู่ระบบ NDP-Kit ให้คนที่ไม่มีหน้าที่เกี่ยวข้อง
- ไฟล์ Excel ที่ส่งออกมามีข้อมูลผู้ป่วย ห้ามส่งต่อในกลุ่มแชท
- ไฟล์รายงาน (.json) ที่แลกกันมีแต่คำสั่ง ไม่มีข้อมูลผู้ป่วย ส่งต่อได้
- รายงานที่รับมาจากหน่วยอื่นให้อ่านคำสั่งก่อนรันทุกครั้ง
